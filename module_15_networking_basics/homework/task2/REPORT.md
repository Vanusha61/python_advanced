# Отчёт о повышении уровня зрелости API

## Текущий уровень (до изменений)
API соответствует уровню 1 по модели Ричардсона:
- Разные URL для разных ресурсов, но используются глаголы в URL (`/add-room`, `/booking`).
- Неправильные HTTP-методы (все POST) и статусы.

## Предложенные изменения
1. Переименование эндпоинтов:
   - `/room` → `/rooms` (множественное число).
   - `/add-room` → `POST /rooms` (создание ресурса).
   - `/booking` → `POST /bookings` (создание бронирования).
   - Добавлен `GET /rooms/{id}` для получения одной комнаты.
   - Добавлен `DELETE /bookings/{id}` для отмены бронирования.

2. Использование правильных HTTP-статусов:
   - 200 OK – успешный GET.
   - 201 Created – успешное создание (комнаты или бронирования).
   - 204 No Content – успешное удаление.
   - 400 Bad Request – невалидный JSON.
   - 404 Not Found – ресурс не найден.
   - 409 Conflict – повторное бронирование.

3. Добавление HATEOAS (уровень 3):
   - В ответах на GET /rooms и GET /rooms/{id} добавлены ссылки на бронирование и на саму комнату (поле `_links`).

## Обоснование
- Единообразие URL и методов упрощает понимание API.
- Правильные статусы помогают клиенту обрабатывать ошибки.
- HATEOAS делает API самодокументируемым.

## Результат
API теперь соответствует уровню 2–3 модели зрелости Ричардсона.
